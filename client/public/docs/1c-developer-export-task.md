# Краткое задание разработчику 1С

Нужно настроить **одностороннюю автоматическую выгрузку из 1С в приложение**. Обратной записи в 1С, Эвотор, кассы и УПД в этой работе нет.

## Куда отправлять

`POST https://<рабочий-домен>/api/integrations/1c/import`

Заголовки:

```http
Content-Type: application/json
X-1C-Key: <ключ из раздела «Импорт 1С»>
```

Ключ выдаёт администратор. Не передавать его в URL, логах или файлах.

## Общие правила

Каждый пакет — один JSON-объект с полями:

```json
{
  "schema_version": "1.0",
  "source_system": "1c_bm_srs",
  "entity": "inventory_snapshots | store_shipments",
  "batch_id": "стабильный-уникальный-id-пакета",
  "mode": "snapshot | delta",
  "generated_at": "2026-09-22T12:00:00Z",
  "business_timezone": "Europe/Moscow",
  "records": []
}
```

Повтор того же `source_system + entity + batch_id` не создаёт дубликат. Количества — числа с точкой и точностью до 0,001. Дата бизнеса — `YYYY-MM-DD`, время — RFC 3339 UTC. В каждой строке должен быть стабильный ID 1С; переименование не меняет ID.

## 1. Полный срез остатков БМ и СРС

Передавать отдельный полный пакет `inventory_snapshots` по каждому изменению среза БМ или СРС.

```json
{
  "entity": "inventory_snapshots",
  "mode": "snapshot",
  "as_of": "2026-09-22T12:00:00Z",
  "records": [{
    "source_record_id": "стабильный-id-строки",
    "location_code": "BM | SRS",
    "product_source_id": "стабильный-id-товара-1с",
    "product_name": "Наименование",
    "quantity_on_hand": 12.5,
    "quantity_available": 11.5,
    "expiration_date": "2026-10-30",
    "business_date": "2026-09-22",
    "as_of": "2026-09-22T12:00:00Z"
  }]
}
```

`BM` и `SRS` — единственные разрешённые основные склады. Для нулевого остатка передаётся строка с `quantity_on_hand: 0`. Отсутствующая строка не означает ноль.

## 2. Расходная накладная БМ/СРС → магазин

При проведении, отмене или исправлении накладной передавать `store_shipments` c `mode: "delta"`.

```json
{
  "entity": "store_shipments",
  "mode": "delta",
  "records": [{
    "shipment_id": "стабильный-id-накладной",
    "revision_id": "версия-выгрузки",
    "source_record_id": "стабильный-id-записи",
    "business_date": "2026-09-22",
    "origin_warehouse_code": "BM | SRS",
    "destination_store_reference": "стабильный-код-магазина-1с",
    "document_number": "Номер накладной",
    "status": "posted | cancelled | corrected",
    "lines": [{
      "line_id": "стабильный-id-строки",
      "product_source_id": "стабильный-id-товара-1с",
      "product_name": "Наименование",
      "quantity": 12.5,
      "unit": "kg | l | piece",
      "expiration_date": "2026-10-30"
    }]
  }]
}
```

Получатель и товар сначала сопоставляются один раз в приложении. Не создавать товар, магазин или связь автоматически при отсутствии подтверждённого соответствия: строка должна попасть в карантин. Отмена и исправление передаются новым `revision_id`; историю уже принятой накладной не перезаписывать.

## 3. Номенклатура и внутренний артикул

У товара 1С должен быть отдельный реквизит **«ID товара сайта»**. После подтверждённого сопоставления в нём хранится внутренний порядковый номер товара сайта — это же значение используется как артикул при последующей выгрузке в Эвотор. Не использовать название, похожий штрихкод или артикул поставщика как автоматическое соответствие.

Для первого запуска разработчик передаёт перечень товаров с `product_source_id`, наименованием, единицей, штрихкодами и этим реквизитом после сопоставления. Алкокод передавать только для алкогольной/пивной позиции; для остальных товаров он не нужен.

## 4. Закупочная цена

Остатки БМ/СРС передают **только количество и срок годности**. Они не являются источником закупочной цены. Для цены будет отдельный пакет `purchase_costs`: товар, цена за базовую единицу, дата действия, основание и, если есть, склад-источник. До публикации этого endpoint не отправлять цену в `inventory_snapshots` или накладных.

Если по БМ и СРС существуют разные цены, 1С передаёт обе с их датой и основанием. Приложение не выбирает цену произвольно по названию склада.

## Приёмка

Отправить один тестовый snapshot на БМ или СРС и одну тестовую накладную на существующий магазин. Проверить ответ `200` и отсутствие дубля при повторной отправке того же `batch_id`.

Не передавать регулярные остатки магазинов, чеки, клиентов, УПД, токены, пароли, карты лояльности или индивидуальные коды маркировки.
