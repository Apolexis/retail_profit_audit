# Автоматическая read-only синхронизация Эвотор

**Дата решения:** 18.09.2026. **Статус:** задания зарегистрированы для закрепленных и нескрытых складов; production-выполнение подтверждено.

Автоматизация сохраняет действующую архитектурную границу: работа с Cloud API V2 выполняется только сервером, токен не попадает в клиент, и никакие `POST`/`PUT`/`PATCH`/`DELETE` в Эвотор не выполняются. Обновление каталога читает номенклатуру, иерархию групп, штрихкоды, маркировочный тип и опубликованный остаток. Для нового ряда документов первая страница всегда запрашивается с `since=01.01.2025` и до даты запуска в Unix-миллисекундах; далее продолжается только opaque cursor этой же серии. Поэтому документы до **01.01.2025** больше не запрашиваются и не импортируются. Фискальные идентификаторы, реквизиты оплат, адреса и технические идентификаторы касс не сохраняются в UI.

| Работа | Расписание | Обоснование |
|---|---:|---|
| Каталог, категории, маркировка, остатки | каждую минуту, один склад по очереди | Это минимально допустимый интервал managed scheduler. Обход каталога ограничен пятью страницами и строго одним закрепленным складом за запуск; фактический запуск укладывается в лимит callback и не создает параллельного fan-out к Эвотор. |
| Чеки и товарные строки | каждую минуту, один склад по очереди | Это минимально допустимый интервал managed scheduler. За запуск читается только одна cursor-страница одной закрепленной нескрытой точки. Незавершенный cursor продолжает обслуживаться до окончания, затем очередь переходит к наименее давно обработанной точке. Ограничение продолжает учитывать публикуемые API заголовки `X-RateLimit-*`. |

Каждая задача идентифицируется непрозрачным UID managed scheduler и проверяется сервером. Запуск, результат или ошибка сохраняются в едином журнале изменений с объектом `operational_sync`; отдельного журнала не создается. Расписание можно приостановить без удаления данных. Источник лимитов: [общая информация REST API Эвотор](https://developer.evotor.ru/docs/rest_overview.html).

## Проверка исполнения

18.09.2026 подтверждено, что оба platform-managed задания включены с минимальным допустимым ритмом **одна минута**. После ограничения callback одним закрепленным складом, cursor-страницей документов и пакетной записью production-журнал зафиксировал успешные HTTP 200 запуски без timeout: каталог — 815 товаров за 10,66 с; документы — 1 000 чеков и 1 466 товарных строк за 7,28 с. Более ранние timeout-записи относятся к версии до этой оптимизации. Это не меняет состав читаемых данных и не добавляет write-вызовов в Эвотор.


## Справка о типе товара для будущей выгрузки

Для read-only отображения кода типа товара используется документированное соответствие из [схем товаров Cloud API V2](https://developer.evotor.ru/docs/rest_api_get_schemas_products.html): `DIETARY_SUPPLEMENTS_MARKED`, `CAVIAR_MARKED`, `GROCERIES_MARKED`, `CANNED_FISH_MARKED`, `BEER_MARKED`, `BEER_MARKED_KEG`, `NOT_ALCOHOL_BEER_MARKED`, `JUICE_MARKED`, `WATER_MARKED`, `DAIRY_MARKED`, `MILK_MARKED`, `ALCOHOL_MARKED`, `ALCOHOL_NOT_MARKED` и `NORMAL`. В интерфейсе этот код служит только прозрачным ориентиром будущего контрактного слоя; какие-либо запросы записи в Эвотор по-прежнему отсутствуют. В документе также подтверждены поля маркированного алкоголя: `alcoholByVolume`, `alcoholProductKindCode`, `tareVolume` и алкокоды.
