# Автоматическая read-only синхронизация Эвотор

**Дата решения:** 18.09.2026. **Статус:** включено для закрепленных и нескрытых складов.

Автоматизация сохраняет действующую архитектурную границу: работа с Cloud API V2 выполняется только сервером, токен не попадает в клиент, и никакие `POST`/`PUT`/`PATCH`/`DELETE` в Эвотор не выполняются. Обновление каталога читает номенклатуру, иерархию групп, штрихкоды, маркировочный тип и опубликованный остаток. Обновление документов читает только следующую cursor-страницу чеков и товарных строк. Фискальные идентификаторы, реквизиты оплат, адреса и технические идентификаторы касс не сохраняются в UI.

| Работа | Расписание | Обоснование |
|---|---:|---|
| Каталог, категории, маркировка, остатки | ежедневно в 04:15 МСК | Полный обход страниц каталога дорогой; ночное окно стабилизирует утреннюю работу и не создает лишнюю нагрузку. |
| Чеки и товарные строки | каждые 15 минут | По одной cursor-странице на закрепленный нескрытый склад, последовательно с небольшой паузой; это ниже установленных поставщиком лимитов, которые API публикует заголовками `X-RateLimit-*`. |

Каждая задача идентифицируется непрозрачным UID managed scheduler и проверяется сервером. Запуск, результат или ошибка сохраняются в едином журнале изменений с объектом `operational_sync`; отдельного журнала не создается. Расписание можно приостановить без удаления данных. Источник лимитов: [общая информация REST API Эвотор](https://developer.evotor.ru/docs/rest_overview.html).
