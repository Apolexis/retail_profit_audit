# Read-only контур Эвотор: продажи, чеки и расчётные остатки

**Статус:** технический контракт для следующей реализации. Исходные финансовые факты и текущие данные остатков не изменяются этой записью.

## Подтверждённая граница источника

Проверка 18.09.2026 выполнена по [официальному руководству по получению остатков](https://developer.evotor.ru/docs/rest_quantities_synchronization_guide.html) и безопасной read-only проверке ответа `GET /stores/{store-id}/documents` через уже настроенный серверный токен. API вернул HTTP 200, курсорную пагинацию `items` / `paging`, а также 35 доступных магазинов. Токен, идентификаторы точек, чеки, персональные данные и сырые документы не выводились.

Эвотор не отдает гарантированное текущее количество товарной строкой каталога. Официальное руководство требует вычислять его из документов: последняя приемка (`ACCEPT`) задаёт остаток; продажа (`SELL`) уменьшает остаток, возврат (`PAYBACK`) увеличивает его. Для продажи учитываются только способы расчёта `CHECKOUT_FULL`, `CHECKOUT_PARTIAL`, `CREDIT_PASS` и `CREDIT_CHECKOUT`. Поэтому «Не посчитан» нельзя заменять выдуманным нулём до завершения исторической загрузки и последующей сверки.

## Подтверждённые поля документов V2

Ответ содержит тип, идентификатор, время закрытия/создания, магазин, кассовую сессию и `body`. Для `SELL` и `PAYBACK` в `body` доступны сумма документа, итоговая сумма, способы оплат и `positions`. Каждая позиция содержит `id`, `uuid`, `product_name`, `quantity`, `initial_quantity`, `measure_name`, `measure_precision`, `price`, `result_price`, `result_sum`, `cost_price`, `tax`, `settlement_method` и вложенные позиции. Z-отчёты дополнительно отдают выручку, наличные и безналичные итоги сессии.

## Предлагаемая следующая модель

Синхронизация должна быть запускаемой администратором, не по загрузке страницы и не по расписанию. Она обходит только закреплённые внутренние склады, читает каталог и документы V2 курсорами, сохраняет минимальные нормализованные поля в новых операционных таблицах и фиксирует одну сводную запись существующим `recordChange`. В интерфейс не попадут адреса, токены, terminal UUID, фискальные номера и реквизиты оплат.

Минимальный результат первого прохода: статус полноты по каждому складу, период документов, число нормализованных чеков/документов, расчётные позиции и их источник. Только после технической проверки дата-диапазона и количества документов такой результат может быть показан в «Остатках» как «Эвотор · расчётный», отдельно от закрытой инвентаризации и ручных корректирующих движений.

## Запреты

Контур остаётся исключительно read-only для Эвотор. Никаких `POST`, изменения каталога/остатков, выгрузки цен, токенов в клиент, автоматического фонового опроса или подмены финансовых фактов не допускается.
