# Проверка возможностей read-only Эвотор Cloud API V2

Проверено 18.09.2026 по официальным источникам: [Обзор API Облака](https://developer.evotor.ru/docs/rest_overview.html) и [получение списка документов](https://developer.evotor.ru/docs/rest_api_get_store_documents.html).

Официальный обзор подтверждает, что Cloud API V2 поддерживает получение данных магазинов, смарт-терминалов и сотрудников, товарной номенклатуры, документов терминала (включая чеки и акты приемки) и данных ОФД. Для постраничных ответов применяется `paging.next_cursor`; перечислены поддерживающие пагинацию коллекции магазинов, терминалов, сотрудников, документов и товаров. API использует `https://api.evotor.ru/`, медиатип `application/vnd.evotor.v2+json` и Bearer/OAuth-авторизацию. Документация одновременно описывает write-методы и массовые операции, поэтому их нельзя задействовать в текущем контуре без отдельного согласования.

Текущая реализация намеренно ограничена server-side read-only каталогом и закрепленным соответствием внутренней точки с Эвотор. Пользователь запросил расширить загрузку на другие закрепленные магазины и их доступные документы/продажи/состав чеков. Это технически совместимо с подтвержденными read-only ресурсами, но требует отдельной схемы хранения идемпотентных read-only снимков, ручного сопоставления кассового товара с общим товаром и отдельной приемки данных. Адреса, токены, terminal UUID и произвольный выбор кассы в UI не выводятся. В текущей задаче не запускалось сохранение новых реальных кассовых данных.
