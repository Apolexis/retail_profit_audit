# Предложение: обратная выгрузка номенклатуры в Эвотор

**Статус:** проект решения. В production не включён. Действующий клиент Эвотор остается **только для чтения**.

## Что есть сейчас

Общий каталог «Рыбного» и привязка магазина к Эвотор существуют независимо. Из Эвотор уже можно безопасно подтянуть для закреплённой точки каталог, штрихкоды, НДС, группу/категорию и разрешенные read-only документы. Никакая карточка товара, цена или остаток **не отправляется обратно**. Поэтому новый товар, созданный во внутренней номенклатуре, не появляется на кассе автоматически; а изменение цены во внутреннем виде цены пока влияет лишь на внутренний контур.

## Как должна работать выгрузка после отдельного решения

| Сценарий | Действие администратора | Безопасный результат |
| --- | --- | --- |
| Новый товар | «Подготовить к выгрузке» в карточке | Создается локальное задание со статусом «Ожидает отправки», без сетевого запроса до подтверждения |
| Карточка уже в Эвотор | «Сопоставить с Эвотор» | Закрепляется сопоставление только со своей кассой; случайный выбор чужой точки запрещен |
| Изменение продажной цены | «Отправить цену в выбранные склады» | В задание попадает только цена вида, назначенного этим складам |
| Отмена | «Отменить задание» до отправки | Локальная запись архивируется; данные Эвотор не меняются |

После явного финального подтверждения сервер, а не браузер, отправит идемпотентный запрос в разрешенный Cloud API. Каждое задание должно содержать внутренний ID товара, целевой склад, версию карточки, тип изменения, контрольный ключ, дату и результат. Токен остается только в server environment. Ответ API и ошибка будут записываться в **существующий общий журнал** без токенов, фискальных данных, адресов и технических идентификаторов.

## Обязательные условия до включения

Перед включением потребуется отдельное согласование API-методов Эвотор для создания/изменения товара и цены, лимитов, списка полей, правил НДС и маркировки, модели отмены, повторов после ошибки, журналирования и прав. Нужны интеграционные тесты в изолированной кассе или песочнице. Без этого нельзя добавлять работающую кнопку выгрузки: она создала бы необратимое изменение кассовой номенклатуры и цен.

## Ответ на текущий вопрос

Сейчас **не нужно и нельзя «выгружать новую номенклатуру» из приложения**: такая возможность намеренно не реализована. Каталог можно обновить только в направлении **Эвотор → приложение** через кнопку «Обновить каталог» у закрепленного склада. После утверждения архитектуры выше новая номенклатура будет сначала попадать в контролируемую очередь, а не уходить в кассу сразу после нажатия «Сохранить».
