# Фактическая товарно-операционная сводка сети и магазинов

**Статус:** будущий модуль. Документ не включает интеграцию, не создает товары, не загружает чеки и не изменяет финансовые факты.

> Сводка показывает **практику продаж**: чеки и строки чеков Эвотор, сопоставленную номенклатуру и историческую себестоимость из 1С. Импортированная финансовая таблица остается независимым теоретическим контуром. В сводке нельзя незаметно подменять один источник другим.

## 1. Показатели и источники

| Показатель | Расчет | Граница достоверности |
| --- | --- | --- |
| Выручка | Закрытые продажи Эвотор минус возвраты за период | Только сопоставленные чеки в подтвержденном диапазоне |
| Чеки | Число закрытых чеков продажи | Возврат не увеличивает число продажных чеков |
| Средний чек | Выручка ÷ число продажных чеков | При нуле чеков выводится `—`, а не `0` |
| Количество/вес | Сумма строк продаж в исходной базовой единице | Килограммы, штуки и иные единицы не складываются в одно общее число |
| Валовая прибыль | Выручка строк продаж − историческая распределенная себестоимость | Не рассчитывается как «чистая прибыль» и помечается, если себестоимость не покрыта |
| Валовая маржа | Валовая прибыль ÷ выручка | Не выводится при нулевой выручке |

Чистая прибыль, аренда, ФОТ, налоги и прочие P&L‑статьи остаются на действующих финансовых страницах. Товарная сводка не выдает валовую прибыль за чистую и не раскрывает финансовые KPI продавцам.

## 2. Изменяемая закупочная себестоимость

Закупочная цена из 1С ведется как неизменяемая **версия себестоимости**, а не как одно редактируемое значение в карточке товара. Каждая версия хранит товар, БМ/СРС, дату действия, цену за базовую единицу, НДС, первичный документ и партию при ее наличии. Исправление из 1С приходит новой ревизией со ссылкой на заменяемую, а не переписывает прежнюю историю.

| Ситуация | Поведение в сводке |
| --- | --- |
| Новая закупка дороже/дешевле | Создается новая версия себестоимости с датой действия; текущая закупочная цена обновляется после проверки пакета |
| Продажа прошлого периода | Использует версию/распределение себестоимости, применимое в дату продажи; сегодняшняя цена не меняет прошлую валовую прибыль |
| Партия известна | Продажа связывается с партией; ее стоимость имеет приоритет |
| Партия неизвестна | Применяется выбранный владельцем метод: скользящая средняя, FIFO или иной согласованный способ; метод виден в детализации |
| Себестоимости нет | Выручка и продажи отображаются, валовая прибыль получает статус «нет данных о себестоимости», а не фиктивный ноль |

FEFO используется для расчетного выбора партии по сроку годности. Это отдельное правило и не заменяет метод распределения себестоимости.

## 3. Страница сети

Визуальная подача наследует уже принятый раздел **«Операционный ритм»**: компактные KPI, управляемый период, наглядная динамика и полная таблица после графика. Это новый самостоятельный экран, а не изменение существующего финансового «Ритма».

1. Верхний уровень: выручка, валовая прибыль, валовая маржа, чеки, средний чек, покрытие сопоставления товаров и себестоимости.
2. Динамика: день/неделя/месяц в зависимости от выбранного периода; переключатели «Выручка», «Валовая прибыль», «Чеки», «Средний чек», «Количество/вес».
3. Сравнение магазинов: одинаковые KPI по каждой точке, с явной пометкой неполных данных.
4. Товарный рейтинг: короткие карточки лидеров и ниже полный ранжированный реестр всех сопоставленных позиций.
5. Очередь качества: не сопоставленные товары, чеки без строки, продажи без себестоимости, возвраты без исходной связи и аномальные количества.

## 4. Страница конкретного магазина

Страница точки использует тот же порядок блоков, но отвечает на вопрос «что произошло в этом магазине». В ней доступны период, динамика, полный список товаров, возвраты и статусы качества данных. Переход из товарной строки открывает детальную историю продаж и связанной себестоимости только в пределах разрешенной роли.

| Рейтинг | Сортировка | Представление единиц |
| --- | --- | --- |
| По выручке | По убыванию `line_total` | Деньги |
| По валовой прибыли | По убыванию валовой прибыли, только с покрытой себестоимостью | Деньги и процент маржи |
| По количеству | По убыванию количества в одной базовой единице | Отдельно `кг`, `шт` и иные единицы |
| По скорости | Среднедневная продажа за выбранный период | Единица товара в день |

Полный список не обрезается «топ‑10»: карточки лидеров ускоряют обзор, но таблица поддерживает поиск, сортировку, фильтр категории и постраничную загрузку всех строк.

## 5. Роли и доступ

| Роль | Что видит |
| --- | --- |
| Администратор | Сеть, все магазины, детализацию себестоимости, качество маппинга и правила расчета |
| Руководитель с правом операционной аналитики | Только назначенные локации и разрешенный уровень детализации; доступ может включаться отдельно от финансового контура |
| Продавец | Отдельная нефинансовая операционная сводка своей точки: остатки, сроки, дефицит/избыток, поступления, рекомендации и заявки; без выручки, прибыли, среднего чека и себестоимости |

Изменение маппинга товара, версии себестоимости, доступа к сводке или метода распределения фиксируется в существующем общем журнале с исполнителем, объектом, значениями `до → после` и причиной, когда она обязательна.

## 6. Визуальный контракт «Ритма»

Новая сводка использует существующую оболочку `AuditShell`, страницу‑введение, сетку равных KPI, карточку динамики, выбор детализации `Дни / Недели / Месяцы`, переключатель сравнения магазинов и полную таблицу под графиком. После основной таблицы размещается компактный блок последних интервалов; он помогает быстро увидеть свежую динамику, но не заменяет полный реестр.

| Элемент «Ритма» | Адаптация для фактической товарной сводки |
| --- | --- |
| Выбор магазинов | Вся сеть, один или несколько разрешенных магазинов; суммирование и раздельные ряды всегда явно подписаны |
| KPI‑карточки | Выручка, валовая прибыль, чеки, средний чек и покрытие себестоимости/маппинга |
| Карточка динамики | Один или несколько показателей: выручка, валовая прибыль, чеки, средний чек, количество/вес |
| Таблица под графиком | Все интервалы выбранного периода с сортировкой, а не только последние восемь |
| Карточки последних интервалов | Последние дни/недели/месяцы с краткими фактическими KPI |
| Полный товарный рейтинг | Самостоятельная таблица после динамики: поиск, фильтры, сортировка и постраничная загрузка без искусственного «топ‑10» лимита |

Светлая тема использует утвержденные нейтральные поверхности и iOS‑синий акцент без кораллового цвета; темная — утвержденные темные поверхности и коралловый акцент без iOS‑синего. Все новые фильтры и сортировки используют тематичные существующие контролы, один focus‑контур, hover без сдвига и проходят приемку на мобильной, средней и широкой ширине.

## 7. Условия первого запуска

1. Read-only получение чеков и строк чеков подтверждено на одном магазине и периоде.
2. Номенклатура Эвотор сопоставлена с 1С по стабильному ID/штрихкоду/единице без автоматической связи по названию.
3. Из 1С получены исторические версии себестоимости и согласован метод распределения при неизвестной партии.
4. Экран явно показывает покрытие данных и не строит денежные KPI из неполного набора.
5. Визуальная приемка выполняется в согласованных светлой и темной темах на мобильной, средней и широкой ширине; используются существующие тематичные контролы, один focus‑контур и паттерны «Ритма».
