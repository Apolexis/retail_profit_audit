# Исследование контракта API Облака Эвотор V2

**Дата:** 17.09.2026  
**Статус:** read-only исследование; это не реализация синхронизации и не разрешение на запись в Эвотор.

## Подтверждено официальной документацией

API Облака V2 вводит новые схемы документов, соответствующие ФФД 1.05 и выше, а также обновленные схемы товаров. В V2 товар и группа товаров являются разными сущностями.[1]

Официально опубликован метод чтения списка документов `GET /stores/{store-id}/documents`.[2] В запросе явно передаются `Accept: application/vnd.evotor.v2+json` и `Content-Type: application/vnd.evotor.v2+json`; API V2 является версией по умолчанию, но заголовки обязательны для защиты от будущей смены default-версии.[5] Ответ `items` содержит до 1000 объектов на страницу; значение `paging.next_cursor` передается следующему запросу как query-параметр `cursor`.[5] Схема документа состоит из общих полей и объекта `body`; среди документированных типов есть `SELL`, `PAYBACK`, `ACCEPT`, `INVENTORY`, `RETURN`, `WRITE_OFF`, кассовые события и другие.[3]

| Вопрос | Подтвержденный вывод |
| --- | --- |
| Целевая версия облачного API | V2 для магазинов, номенклатуры и будущей истории продаж |
| Операции на первом этапе | Только чтение; создание, обновление и удаление в облаке/на кассах запрещены |
| Каталог | Стабильные идентификаторы, иерархия, товарные единицы, точность и штрихкоды сохраняются без угадывания по названию |
| Продажи | Для аналитики используются документы `SELL`, возвраты — `PAYBACK`; финансовая таблица сайта не изменяется |
| Курсор | `paging.next_cursor` следующей страницы передается как `cursor`; повтор курсора не должен создавать дубль чека |
| Детали запроса документов | В первом запросе допустимы `since` и `until`: миллисекунды Unix; `since` включительно, `until` исключительно. Оба параметра задаются только на первой странице, продолжение выполняется через `cursor` |
| Фильтр типа | В опубликованном методе нет query-параметра `type`; не передавать вымышленный фильтр. После получения страницы аналитический контур отбирает только `SELL` и `PAYBACK`, прочие типы не смешивает с продажами |
| Размер страницы и доступ | До 1000 объектов в `items`; дальнейшие страницы по `paging.next_cursor`. Облако дополнительно фильтрует выдачу по разрешениям приложения и терминалам, на которых приложение установлено |
| Глубина истории чеков | Документация разрешает не задавать `since`, чтобы получить документы с момента создания магазина; поддержка Эвотор дополнительно подтвердила доступность с момента регистрации терминала. Шести месяцев как лимита нет |

## Фактическая read-only проверка текущего доступа

Без изменения данных подтверждена работа защищенного серверного доступа к списку магазинов и номенклатуре. Ответы V2 используют `snake_case` и курсорную форму чтения документов. История продаж реально подходит для статистики по товарным строкам; ранее безопасно подтверждены поля количества, цены, штрихкода, единицы и маркера для товарных строк, однако окончательный V2-запрос ограниченного периода требуется закрепить отдельно.

## Официальное подтверждение периода истории

17.09.2026 поддержка Эвотор направила актуальную ссылку на метод документов и сообщила: «Сроки можете выбрать любые, документы будут с момента регистрации терминала». На указанной странице документации для `GET /stores/{store-id}/documents` описано: `since` задает включительную нижнюю границу в миллисекундах, `until` — исключительную верхнюю границу в миллисекундах; эти параметры передаются только в первом запросе серии страниц. Если требуется весь доступный архив с момента создания магазина, параметр `since` не указывается.[2]

Следовательно, **ограничения «только шесть месяцев» нет**. Для аналитики за последний год или два года достаточно начать первую cursor-серию с границы нужного периода. Практическая нижняя граница конкретной точки зависит не от лимита API, а от ее даты создания/регистрации и фактического наличия данных до этой даты. До запуска регулярного чтения preview одной точки должен показать самую раннюю возвращенную дату, но не требуется дополнительно запрашивать поддержку о глубине хранения.

Тип документа в полученном архиве определяется по полю документа (`SELL`, `PAYBACK` и другие документированные значения), а не предполагаемым query-параметром типа. В опубликованном методе такого параметра нет: не добавлять его в запрос. Регулярный импорт сохраняет/агрегирует только `SELL` и `PAYBACK`; остальные документированные типы не становятся продажами и, при необходимости, учитываются отдельным контуром.

17.09.2026 выполнен один дополнительный серверный запрос `GET /stores/{store-id}/documents` к первой доступной точке с заголовком V2 и без параметров. Он вернул `200`, JSON-объект без `items` и без `next_cursor`. Имена магазинов, значения токена, данные чеков, покупателей, товаров и полный ответ не выводились и не сохранялись. Пустая первая страница одной точки не доказывает отсутствие чеков в других точках и не устанавливает период хранения; это только подтверждает, что endpoint принимает базовый read-only запрос.

## Подтвержденная модель полей каталога

Доступная публичная REST-схема помечена как API `v1.0.9`; поэтому она используется только как документированное подтверждение имен товарных полей и **не** подменяет V2-контракт для чтения истории. В карточке товара перечислены `uuid`, `code`, `barCodes`, `alcoCodes`, `name`, `price`, `quantity`, `costPrice`, `measureName`, `tax`, `allowToSell`, `articleNumber`, `parentUuid`, `group`, `type`, `alcoholByVolume`, `alcoholProductKindCode` и `tareVolume`.[4]

| Поле Эвотор | Использование в проекте |
| --- | --- |
| `uuid`, `code`, `parentUuid` | Разовый ручной маппинг с 1С и дальнейшая устойчивая связь; совпадение только по названию запрещено |
| `barCodes`, `alcoCodes` | Импортируемые признаки для сверки; ручная карточка сайта допускает несколько значений, разделенных только `;` |
| `measureName`, `quantity` | Исходная единица и фактическое количество; техническое значение `дроб` показывается пользователю как `кг`, без потери исходного значения |
| `tax` | Наблюдаемый кассовый признак НДС; в карточке сайта ставка по умолчанию 10% с управляемым изменением на 22% |
| `type` | Управляемый выбор категории маркировки; не создавать категорию автоматически при неоднозначности |
| `alcoholByVolume`, `alcoholProductKindCode`, `tareVolume`, `alcoCodes` | Показывать только при выбранной маркировке «Алкоголь» или «Маркированное пиво» |

Значения исторической публичной V1-схемы НДС не считаются нормативным справочником для проекта: фактическая ставка товара подтверждается текущим каталогом Эвотор и данными 1С.

## Следующее техническое действие

Перед запуском регулярного чтения выполнить на одной точке минимальный server-side read-only preview: первая страница `GET /stores/{store-id}/documents?since=<начало периода в ms>&until=<конец периода в ms>`, затем продолжать только по `cursor` до исчерпания. Preview не выводит токен, имена покупателей, данные чеков или полный ответ; он фиксирует только статус запроса, самую раннюю/позднюю дату, число страниц и типы документов. Первый приемочный диапазон — последний год, затем при необходимости два года. V1 не включать в продуктовый контур: он использовался лишь для диагностической сверки структуры и доступности истории.
