# Исследование контракта API Облака Эвотор V2

**Дата:** 17.09.2026  
**Статус:** read-only исследование; это не реализация синхронизации и не разрешение на запись в Эвотор.

## Подтверждено официальной документацией

API Облака V2 вводит новые схемы документов, соответствующие ФФД 1.05 и выше, а также обновленные схемы товаров. В V2 товар и группа товаров являются разными сущностями.[1]

Официально опубликован метод чтения списка документов `GET /stores/{store-id}/documents`.[2] В запросе должны явно передаваться `Accept: application/vnd.evotor.v2+json` и, если есть тело, соответствующий `Content-Type`. Ответы с массивом `items` используют курсорную пагинацию: значение `paging.next_cursor` передается следующему запросу как query-параметр `cursor`.[1] Схема документа состоит из общих полей и объекта `body`; для продаж присутствует тип `SELL`, для возвратов — `PAYBACK`.[3]

| Вопрос | Подтвержденный вывод |
| --- | --- |
| Целевая версия облачного API | V2 для магазинов, номенклатуры и будущей истории продаж |
| Операции на первом этапе | Только чтение; создание, обновление и удаление в облаке/на кассах запрещены |
| Каталог | Стабильные идентификаторы, иерархия, товарные единицы, точность и штрихкоды сохраняются без угадывания по названию |
| Продажи | Для аналитики используются документы `SELL`, возвраты — `PAYBACK`; финансовая таблица сайта не изменяется |
| Курсор | `paging.next_cursor` следующей страницы передается как `cursor`; повтор курсора не должен создавать дубль чека |
| Детали запроса документов | Точный набор фильтров по периоду и типам должен быть подтвержден по рабочему V2 OpenAPI или минимальным read-only запросом до включения регулярного импорта |
| Глубина истории чеков | Официальная доступная страница не устанавливает срок хранения. Подтвержденное ранее окно около шести месяцев — **не лимит**, а только фактически проверенная глубина доступа |

## Фактическая read-only проверка текущего доступа

Без изменения данных подтверждена работа защищенного серверного доступа к списку магазинов и номенклатуре. Ответы V2 используют `snake_case` и курсорную форму чтения документов. История продаж реально подходит для статистики по товарным строкам; ранее безопасно подтверждены поля количества, цены, штрихкода, единицы и маркера для товарных строк, однако окончательный V2-запрос ограниченного периода требуется закрепить отдельно.

> **Вывод по вопросу о шести месяцах.** На 17.09.2026 публичная документация Эвотор подтверждает чтение документов и cursor-пагинацию, но не публикует предел глубины истории. Нельзя утверждать, что доступно «только полгода», и нельзя обещать более длинный период без безопасной проверки или ответа поддержки Эвотор.

17.09.2026 выполнен один дополнительный серверный запрос `GET /stores/{store-id}/documents` к первой доступной точке с заголовком V2 и без параметров. Он вернул `200`, JSON-объект без `items` и без `next_cursor`. Имена магазинов, значения токена, данные чеков, покупателей, товаров и полный ответ не выводились и не сохранялись. Пустая первая страница одной точки не доказывает отсутствие чеков в других точках и не устанавливает период хранения; это только подтверждает, что endpoint принимает базовый read-only запрос.

## Подтвержденная модель полей каталога

Доступная публичная REST-схема помечена как API `v1.0.9`; поэтому она используется только как документированное подтверждение имен товарных полей и **не** подменяет V2-контракт для чтения истории. В карточке товара перечислены `uuid`, `code`, `barCodes`, `alcoCodes`, `name`, `price`, `quantity`, `costPrice`, `measureName`, `tax`, `allowToSell`, `articleNumber`, `parentUuid`, `group`, `type`, `alcoholByVolume`, `alcoholProductKindCode` и `tareVolume`.[4]

| Поле Эвотор | Использование в проекте |
| --- | --- |
| `uuid`, `code`, `parentUuid` | Разовый ручной маппинг с 1С и дальнейшая устойчивая связь; совпадение только по названию запрещено |
| `barCodes`, `alcoCodes` | Импортируемые признаки для сверки; ручная карточка сайта допускает несколько значений, разделенных только `;` |
| `measureName`, `quantity` | Исходная единица и фактическое количество; техническое значение `дроб` показывается пользователю как `кг`, без потери исходного значения |
| `tax` | Наблюдаемый кассовый признак НДС; в карточке сайта ставка по умолчанию 10% с управляемым изменением на 22% |
| `type` | Управляемый выбор категории маркировки; не создавать категорию автоматически при неоднозначности |
| `alcoholByVolume`, `alcoholProductKindCode`, `tareVolume`, `alcoCodes` | Показывать только при выбранной маркировке «Алкоголь» или «Маркированное пиво» |

Значения исторической публичной V1-схемы НДС не считаются нормативным справочником для проекта: фактическая ставка товара подтверждается текущим каталогом Эвотор и данными 1С.

## Следующее техническое действие

Перед запуском регулярного чтения сначала получить документальное подтверждение фильтра периода и типов V2. Только после этого на одной точке допустим GET-запрос V2 с подтвержденными параметрами и курсором: он фиксирует точную форму запроса и обработку продолжения страниц по сохраненному курсору. Если публичная документация не раскрывает эти фильтры, следующий допустимый шаг — один минимальный read-only запрос без вывода имен, данных чеков, клиентов, токена или полного ответа; он может подтвердить лишь принимаемые сервером параметры и наличие страницы. Если и это не дает доказательства глубины истории, запросить у поддержки Эвотор ссылку на актуальную V2 OpenAPI-спецификацию и подтверждение периода хранения. V1 не включать в продуктовый контур: он использовался лишь для диагностической сверки структуры и доступности истории.
