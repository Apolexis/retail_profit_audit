# Контракт заявок и печатных групп магазинов

**Статус:** реализовано в операционном контуре; версия модели — **18.09.2026**. Контур заявок не меняет номенклатуру, остатки, данные Эвотор или финансовые факты.

## Сущности и жизненный цикл

| Сущность | Назначение | Изменяемость и защита |
| --- | --- | --- |
| **Заявка магазина** | Один черновик на магазин с количеством и комментарием по позиции. Товар берется только из общего активного справочника с включенной видимостью «В заявках». | Продавец/руководитель могут менять только черновик назначенной точки. Закрытие доступно руководителю или администратору и делает строки неизменяемым снимком. |
| **Строка заявки** | Снимок бизнес-номера, названия, категории, единицы, количества и комментария товара на момент сохранения. | После закрытия не пересчитывается из последующих изменений справочника. |
| **Группа магазинов для печати** | Редактируемая именованная подборка складов: например, «Область 1», «Город», «Область 2». | Администратор задает ее через настройку каждого склада, создает, переименовывает, скрывает или удаляет группу. Удаление отсоединяет только настройки складов и не меняет заявки, цены, товары или историю. |
| **Категория печати** | Именованная подборка категорий общего каталога: например, «СРС» или «СРС В/У». | Администратор добавляет категории и вложенные категории печати. Циклическая вложенность запрещена. Удаление отсоединяет только конфигурационные связи. |
| **Режим категории печати** | Определяет форму листа для конкретной категории. | «Отдельный лист на магазин» создает один лист на магазин; «Все магазины вместе» собирает строки всех магазинов выбранной группы в один лист. |

Для каждой категории печати администратор выбирает группу складов-источников для индикатора и **максимальный запас магазина в днях** (по умолчанию два дня, диапазон от одного до четырнадцати). Продавец видит только качественный сигнал источника — «мало», «достаточно» или «много», без точного остатка. Рекомендация использует продажи за последние семь дней, запас магазина и норму категории: при покрытии выше нормы она рекомендует не заказывать позицию в этот день.

Открытие заявки не создает движение остатков и не является заказом в Эвотор или поставщику. Номенклатура, внутренняя себестоимость и цены не дублируются в заявках; в строке хранится только зафиксированное содержание заявки.

## Печать

Печать строится как отдельный A4 portrait-документ, а не как рабочая страница. Администратор выбирает дату, группы магазинов и категории печати. В источник попадают **только закрытые заявки** выбранной даты от нескрытых магазинов. Для вложенной категории в подборку входят товары всех дочерних групп.

| Область печати | Состав | Разрыв страницы |
| --- | --- | --- |
| Группа магазинов + категория печати | Только магазины группы с закрытыми заявками и подходящими строками | Новый лист для каждой сформированной подборки |
| «Отдельный лист на магазин» | Один магазин и подходящие товары | Один самостоятельный A4-лист на магазин |
| «Все магазины вместе» | Последовательность магазинов с подходящими товарами | Один общий A4-лист на группу магазинов и категорию |
| Строка | Бизнес-номер, наименование, количество с единицей, комментарий; в общем листе также номер заявки | Не скрывает пустой комментарий, но не выводит технические ID |

Заголовок магазина и заголовки колонок используют `Arial Black`; строки — `Arial` 9 pt. Печатная разметка не содержит кнопок, полей ввода, контуров рабочего интерфейса, навигации, адресов, токенов, terminal UUID или иных технических идентификаторов.

## Доступ и единый audit

Продавец видит и редактирует только черновик своей единственной назначенной точки. Руководитель работает только с назначенными точками, может закрыть заявку и не получает доступ к себестоимости. Администратор управляет группами, закрытием и печатью. Создание черновика, изменение комментария, добавление, изменение и удаление строки, закрытие, удаление черновика и формирование печати фиксируются через существующий `recordChange`; отдельный журнал не создается.

## Преднамеренные границы

Контур не передает заявки, товары или количества в Эвотор. Он не меняет остатки: корректировка остатка остается отдельной закрываемой инвентаризацией. Флаг «В заявках» в карточке товара определяет только доступность позиции при наборе черновика; он не скрывает товар из общего каталога и не изменяет read-only интеграцию Эвотор.
