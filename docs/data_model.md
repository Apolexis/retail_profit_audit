# Модель данных операционного аудита

## Объекты

| Объект | Назначение | Ключевое правило |
|---|---|---|
| `stores` | Справочник торговых точек | Имя нового листа создает новую точку; переименованный лист рассматривается как новая точка, пока пользователь не выполнит объединение вручную. |
| `periods` | Месячные периоды отчетности | Уникальны по комбинации `store_id + month_date`; период хранит исходный номер месяца и год из имени файла. |
| `metrics` | Детальные строки P&L, товара и остатков | Уникальны по `period_id + metric_code`, что предотвращает дубли одной статьи за один месяц. |
| `imports` | Журнал загрузок | Хранит файл, дату, статус, количество созданных/обновленных периодов и ошибки разбора. |
| `hidden_stores` | Состояние включения точки в аналитические срезы | Скрытая точка остается в базе и журнале, но не входит в выборки, графики и селекторы. |

## Импорт и конфликты

Первичный импорт добавляет все распознанные магазины и месяцы. При повторной загрузке приложение сравнивает каждую запись с ключом `магазин + дата + показатель`. Если найдена запись за тот же месяц, пользователь выбирает один из трех вариантов: **заменить** старые значения данными файла; **открыть редактирование** существующей записи; либо **отменить** операцию без изменений.

## Границы автоматизации

Первые три листа рабочей книги не загружаются. Все последующие листы интерпретируются как магазины. Исходный XLSX сохраняется в файловом хранилище для аудиторского следа; расчеты интерфейса строятся только по нормализованным значениям в базе. Расчеты наценки, маржи, покрытия и риск-сигналы пересчитываются из актуальных записей и не записываются поверх фактов.
