# Аналитика «Рыбный»

**Аналитика «Рыбный»** — закрытая управленческая система для импорта Excel-книг торговых точек, анализа прибыли, расходов, товарного запаса и сценариев улучшения экономики. Система разделяет исходные факты, аналитические расчеты и права доступа, поэтому пользователь видит только разрешенные магазины, а значимые действия остаются в аудиторском следе.

> **Безопасность.** В репозитории нет исходных Excel-книг, паролей, токенов или сессий. Конфиденциальные значения передаются через защищенную конфигурацию окружения и не должны попадать в Git, логи или интерфейс.

## Возможности

| Контур | Что реализовано |
|---|---|
| Аналитика | Сводка, сравнение месяцев, цены, расходы, остатки, профиль магазина, портфель, сравнение магазинов, динамика периодов, многосерийный «Ритм» с таблицей деталей, сценарный центр «Пилот» и «Прогноз». Общий компонент предоставляет «Волну», «Столбцы» и непрозрачное «Наложение» для каждого информативного многоточечного ряда. |
| Периоды | Единый двухэтапный календарь на аналитических страницах: первый клик задает начало, второй — конец. Есть стандартные интервалы, включая «С начала этого года» до текущей локальной даты пользователя. |
| Импорт Excel | Поддержка `.xlsx` и `.xlsm`, включая защищенные OOXML-книги с серверным чтением в памяти, компактный бинарный предпросмотр до записи, диагностика распознавания по листам, конфликты «магазин + дата», режим сохранения ручных сумм, обязательный календарный диапазон, скачивание точного исходника, история, удаление конкретного импорта и ручное объединение переименованных точек. |
| Факты | Редактирование по связке **магазин + точная дата + показатель**, добавление и удаление отдельных показателей, изменение их аналитического вида, скрытие из расчетов без удаления из базы и массовое удаление календарного диапазона с предпросмотром последствий. |
| Доступ | Вход по российскому мобильному номеру, роли администратора и аналитика, тумблеры «Нет / Просмотр / Изменение» по каждому магазину и отдельный уровень импорта «Нет / Загрузка / Изменение», безопасное удаление учетных записей и администраторская смена чужого пароля с завершением сессий. На экране входа доступна светлая/темная тема. После обычного входа можно добровольно включить ключ доступа: системный passkey, Face ID, Touch ID, Windows Hello или PIN подтверждаются на устройстве, а телефон и пароль остаются резервным способом. |
| Контроль | Центр сигналов, переход к первоисточнику события, краткий журнал только конкретных изменений, настраиваемые пороги, агрегированный итог рисков после крупного импорта и защищенная постраничная детализация событий конкретной книги. Администратор может вручную отправить текст в ленту всех активных учетных записей; web‑push получают только устройства с добровольно включенной подпиской. |
| Отчеты | Регулярная управленческая сводка для администраторов за предыдущую календарную неделю или завершенный календарный месяц. Сохраненная сводка открывается явным действием «Показать»; день, время по Москве, период и включение расписания настраиваются в интерфейсе. |
| Адаптивность | На средней и мобильной ширине навигация переходит в выдвижное меню с плоскими сворачиваемыми группами; сценарные блоки «Пилота» и верхние действия помещаются в ширину 320 px без горизонтальной прокрутки. |

## Аналитические разделы

| Раздел | Управленческий вопрос | Ключевые срезы |
|---|---|---|
| Сводка | Какова экономика сети и конкретной точки? | Выручка, чистая прибыль, маржа, сезонность, навигация в дочерние разделы. |
| Месяцы | Где и когда изменилась динамика? | Показатель по месяцам, сетевой срез и точка, общий календарный период. |
| Цены | Как соотносятся закупки и продажи Коп./Мор.? | Общий товарный поток и отдельные категории по магазинам. |
| Расходы | Какие статьи требуют управленческой проверки? | Суммы, доля в выручке, сетевые медианы и сигналы отклонения. |
| Остатки | Сколько денег находится в товаре и каков риск запаса? | В режиме «Все магазины» — сумма первого/последнего снимка каждой доступной точки; покрытие сети и **медиана покрытия типичной точки** в днях, изменение, перемещения, уценка и списания. |
| Динамика | Как сопоставить разные годы и произвольные интервалы? | Независимый основной и сравнительный периоды, поэтому раздел готов к будущим импортам 2027+ без переработки. |
| Прогноз | Когда ожидать просадку или всплеск потока? | Факт доступных месяцев текущего года, текущий краткосрочный темп и сезонная структура прошлого года. Будущие месяцы явно маркированы способом расчета, а не заполнены нулями. |
| Операционный ритм | Как меняется темп по месяцам, неделям и дням? | Множественный выбор показателей и магазинов, график с режимами «Волна / Столбцы / Наложение», карточки последних интервалов и полная таблица. Продажи, закупки, списания, НДФЛ 22%, банк и налоги остаются на фактической дате; только согласованные ежемесячные статьи материализуются по правилам импорта. |
| Пилот | Как оценить эффект управленческой гипотезы? | Режим одной точки или сети; цена, объем, общая закупочная цена, закупочная цена Коп., закупочная цена Мор., списания, расходы и запас. Для нескольких точек сценария закрытия видны выбывающие закупки Коп./Мор./вместе, остаток, общий итог и статьи прекращаемых расходов, а также поток «исходная прибыль → изменение → итог» — без изменения базы. |
| Еженедельные отчеты | Что руководителю проверить по итогам прошлой недели? | Последний доступный P&L-срез, топ прибыли, риски, количество действий и история отчетов. |

## Импорт и данные

### Правила разбора Excel

1. Год определяется по имени загружаемого файла.
2. Первые три листа считаются техническими и пропускаются.
3. Каждый лист, начиная с четвертого, считается отдельным магазином.
4. Распознаются заполненные месяцы и отдельные календарные дни внутри каждого блока; каждая дневная строка сохраняется собственной датой.
5. Для нового импорта администратор может выбрать поддерживаемые ежемесячные статьи, которые будут материализованы по дням. Эта настройка не меняет существующие факты и книги. Чистая прибыль не выбирается: она распределяется не поровну, а пропорционально фактической дневной расходной нагрузке с точным итогом месяца.
6. При совпадении **магазина и даты** администратор выбирает один из трех явных вариантов: полностью заменить факт, пропустить совпадение или обновить импортные суммы, сохранив ручные изменения сумм, внесенные после прошлого импорта.
7. Новый или переименованный лист образует отдельную точку. Если это тот же магазин, объедините точки через страницу импорта и выберите правило обработки совпадающих дат.

Первичный источник хранится с точной датой каждой строки книги. Ручные факты также можно создать на любую дату. В редакторе «добавить показатель» означает создать одну строку из трех частей: выбранный магазин, дата и аналитический показатель с суммой. При попытке добавить уже существующий показатель система открывает его редактирование, а не создает дубликат. Диапазон календарного импорта является частью команды записи: в базу попадают только строки с датами внутри выбранных границ включительно. Проверенный повторный импорт книги 2026 ограничен 01.01.2026–31.08.2026; даты сентября–декабря в нём не созданы.

Показатель можно переименовать только в одну из поддерживаемых аналитических категорий, чтобы его сумма продолжила правильно участвовать в графиках и расчетах. Для магазина доступно отдельное переименование: идентификатор точки, периоды, права и история остаются прежними. Если новое название уже занято, система не объединяет данные автоматически и направляет к отдельному сценарию объединения точек. Каждую завершенную книгу можно скачать как точный исходный файл; скачивание не пересобирает и не меняет Excel.

Режим «Сохранить ручные правки» защищает только вручную отредактированные **суммы**. Скрытие факта является отдельной настройкой аналитической видимости: она сохраняется, но не блокирует загрузку обновленного значения из файла.

### Удаление диапазона и расчетная детализация

Массовое удаление доступно только администратору. До подтверждения система показывает количество дат, показателей и магазинов, а после действия сохраняет в журнале область, диапазон и последствия. Удаление затрагивает только периоды с датами внутри выбранного интервала.

При импорте продажи, закупки, списания и прочие операционные значения сохраняются по первичным дневным строкам Excel. Поддерживаемые ежемесячные статьи, выбранные в настройке будущих импортов, **сразу материализуются в дневных фактах** равными календарными долями внутри месяца с точной месячной суммой. Чистая прибыль — отдельное неизменяемое правило: она распределяется между днями пропорционально фактической дневной расходной нагрузке и также сохраняет точный месячный итог. НДФЛ 22%, банк и «Налоги» остаются в фактической дате. `stock_open` и `stock_close` остаются снимками и не участвуют в недельно-дневном потоке.

## Доступ, сигналы и журнал

| Роль/уровень | Возможности |
|---|---|
| Администратор | Вся сеть, импорты, факты, пользователи, доступы, сигналы, журнал и регулярные отчеты. |
| Аналитик — просмотр | Только назначенные магазины, без изменения фактов или загрузки книг. |
| Аналитик — изменение | Факты только тех магазинов, где выбран тумблер «Изменение». |
| Импорт — Нет | Не может открыть предпросмотр, загрузить, заменить, удалить или скачать исходник. |
| Импорт — Загрузка | Может проверять и добавлять новую книгу с режимом пропуска совпадений; не может заменять, удалять или скачивать исходник. |
| Импорт — Изменение | Дополнительно может заменять/удалять импортированные данные и скачивать точную исходную книгу. |

Защита реализована в API, а не только скрытием кнопок. Для сигналов доступны прямые переходы к первоисточнику. Перед подтверждением импорта система показывает отдельные риски: состав наличных статей, НДФЛ 22%, прочие затраты, прибыль, списания и запас — в соответствии с включенными порогами. После крупной загрузки пороговые события приходят одним агрегированным итогом: действие «Открыть детали» открывает защищенную постраничную выдачу реальных событий именно этой книги. Критичные уведомления видит администратор при входе; для магазина они также могут быть получены аналитиком с назначенным доступом. Журнал фиксирует, в том числе, импорты, удаление, объединение, права, видимость магазина/факта, passkey и изменение метрик. Откат доступен только там, где исходное состояние позволяет выполнить безопасное восстановление. При удалении учетной записи очищаются ее сессии, passkey, доступы и персональные уведомления; удалить текущую учетную запись или последнего активного администратора нельзя.

## Еженедельный отчет

Регулярная сводка формируется за **предыдущую календарную неделю** или за **последний завершенный календарный месяц** — режим задается администратором. В настройках раздела «Отчеты» администратор выбирает день недели, время **по Москве**, период и включает либо выключает расписание. Устойчивый серверный запуск выполняется через платформенный Heartbeat, не зависит от открытого браузера и защищен проверкой доверенного запуска.

В отчете показаны выручка, чистая прибыль, маржа, количество точек, убыточные магазины, действия за соответствующий период, лидеры прибыли и точки риска. P&L-часть строится по точному дневному окну выбранной недели или месяца.

## Локальная разработка

```bash
pnpm install
pnpm dev
```

| Команда | Назначение |
|---|---|
| `pnpm dev` | Запускает клиент и сервер в режиме разработки. |
| `pnpm check` | Проверяет типы TypeScript. |
| `pnpm test` | Запускает Vitest-тесты. |
| `pnpm drizzle-kit generate` | Создает SQL-миграцию после изменения `drizzle/schema.ts`. |

Для разработки требуются переменные окружения платформы для подключения к БД, серверных сессий и защищенного хранилища. Не создавайте `.env` с реальными значениями в Git.

## Правила безопасной доработки

1. При изменении схемы обновите `drizzle/schema.ts`, сгенерируйте миграцию, прочитайте SQL и только затем применяйте ее.
2. Удаляйте книгу только через операцию удаления импорта, а не прямой очисткой метрик: это сохраняет целостность периодов и удаляет пустые магазины корректно.
3. Не заменяйте действующие страницы новыми срезами без прямого решения: новые управленческие блоки добавляйте отдельным экраном или явно отделенным разделом.
4. Любое правило доступа реализуйте одновременно в серверной проверке и интерфейсе.
5. Перед публикацией запускайте `pnpm check`, `pnpm test`, проверяйте свежие журналы сервера и актуализируйте `todo_store_permissions_notifications.md`.

## Возможные следующие улучшения

Логичное развитие системы — отдельный контур **план‑факт** по выручке, прибыли, аренде и ФОТ; выгрузка недели в PDF; канал корпоративного мессенджера для критических сигналов; анализ оборачиваемости по товарным категориям. Для любого нового модуля сохраняйте главный принцип: **факт неизменяемо хранится в базе, а выводы и визуализации должны быть воспроизводимы из него**.
